1. PROJECT GOAL
================================================================================

Objective: Use Machine Learning to PREDICT the minimum cost of Matrix Chain
Multiplication (MCM) — replacing or accelerating the O(n³) Dynamic Programming
(DP) algorithm with a trained model that runs in near-constant time O(1).

Target: Achieve predictions within ~1-5% of the exact DP solution (MAPE < 5%).

Outcome: GOAL NOT FULLY ACHIEVED. Best models reach ~24-35% MAPE in raw cost
space. R² in log-space is high (~0.98), but raw-space percentage errors remain
large, especially on edge cases (bottleneck/spiky chains: 85-914% error).

7. WHY WE DID NOT ACHIEVE THE GOAL (<5% MAPE)
================================================================================

ROOT CAUSE #1: MCM IS FUNDAMENTALLY A COMBINATORIAL / STRUCTURAL PROBLEM
-------------------------------------------------------------------------
The optimal MCM cost depends on the EXACT parenthesization of the chain.
A chain of n matrices has Catalan(n) possible parenthesizations (~exponential).
No summary statistics or even padded raw dimensions can capture the recursive
subproblem structure that DP exploits. The cost is determined by WHICH splits
are chosen at WHICH positions — this is a global structural dependency that
flat feature vectors cannot represent.

Example: [10, 1000, 10, 1000, 10] — the cost depends entirely on recognizing
that multiplying the "10" bottleneck dims first dramatically reduces cost.
Our features can flag "has_bottleneck=1" but cannot encode WHERE the bottleneck
is relative to all other splits.

ROOT CAUSE #2: ENORMOUS TARGET RANGE (MULTIPLE ORDERS OF MAGNITUDE)
--------------------------------------------------------------------
MCM costs span from ~10 to ~10^9 (10 orders of magnitude). Even with log
transforms (log1p or log10), a small error in log-space translates to a
MASSIVE error in raw-space:
  - 0.1 error in log10 space = ±26% in raw space
  - 0.3 error in log10 space = ±100% in raw space
  - 0.5 error in log10 space = ±216% in raw space

This is why R² looks great (0.98+) but MAPE is terrible (24-35%):
R² measures variance explained in log-space where the spread is small,
but MAPE measures percentage error in raw-space where the spread is huge.

ROOT CAUSE #3: SPIKY / BOTTLENECK CHAINS ARE DISTRIBUTION OUTLIERS
-------------------------------------------------------------------
Spiky chains like [10, 1000, 10, 1000, 10] create extreme cost structures
where the optimal parenthesization matters enormously. These represent only
10-15% of training data but have the most complex cost landscape. Models
underfit these patterns because:
  - They are underrepresented (only 10-15% of data)
  - Their cost structure is highly nonlinear
  - Small changes in dimension positions cause huge cost swings

ROOT CAUSE #4: FEATURES LOSE STRUCTURAL INFORMATION
----------------------------------------------------
Even with 131 features including padded raw dims and pairwise products:
  - Padded raw dims preserve ORDER but not the recursive SPLIT structure
  - Pairwise products capture adjacent costs but not OPTIMAL SPLIT SELECTION
  - The DP solution requires considering ALL possible splits at ALL positions
    simultaneously — this is a global optimization that local features miss
  - 51 padded dimensions + 50 products = fixed-size representation of a
    variable-length RECURSIVE problem → fundamental information loss

ROOT CAUSE #5: WRONG PROBLEM FORMULATION
-----------------------------------------
We formulated this as a REGRESSION problem: predict cost from features.
But MCM is really an OPTIMIZATION problem: find the best parenthesization.
A better ML formulation might be:
  - Predict the optimal SPLIT POINT at each recursion level
  - Use a sequence-to-sequence model (Transformer/RNN) that can process
    the chain sequentially and learn the recursive structure
  - Use reinforcement learning to learn a splitting policy
  - Use GNNs to model the subproblem dependency graph


================================================================================
8. WHAT WE COULD DO DIFFERENTLY (FUTURE DIRECTIONS)
================================================================================

1. TRANSFORMER ARCHITECTURE: Use self-attention to model relationships between
   ALL dimension pairs simultaneously, not just adjacent ones.

2. SEQUENCE-TO-SEQUENCE: Treat the chain as a sequence and predict split points
   rather than the final cost directly.

3. GRAPH NEURAL NETWORKS: Model the MCM subproblem structure as a graph where
   nodes are subchains and edges are dependencies.

4. CURRICULUM LEARNING: Train on small chains first (n=3-5 where patterns are
   simpler) then progressively increase to larger chains.

5. MORE DATA FOR HARD CASES: Generate 10x more bottleneck/spiky samples to
   balance the distribution for these worst-case scenarios.

6. ENSEMBLE WITH DP FALLBACK: Use ML for quick estimate, fall back to DP when
   the predicted cost has high uncertainty.

7. PREDICT LOG-RATIOS: Instead of predicting absolute cost, predict the ratio
   of optimal cost to some baseline (e.g., greedy cost), which is bounded.
